# Known limitations at Stage 6

- No production deployment or organizational infrastructure validation has occurred. Identity, session policy, TLS/WAF, malware scanning, encrypted object evidence storage, centralized logs, alerts, backup retention, RPO/RTO and support contacts require IT implementation and evidence.
- D1/SQLite is the preserved Worker-compatible architecture, not the baseline's preferred PostgreSQL. Platform remote migration/export commands require an approved account and were not exercised by this repository-only stage.
- Repository signature scanning is deterministic defense in depth, not a replacement for the organization's secret scanner, malware scanner, DLP, SAST or human review. GitHub Dependency graph / Advanced Security is disabled, so `dependency-review-action` is unavailable and has been replaced in CI by frozen-lock reproduction, complete-tree output, sha512 lockfile-integrity validation, registry-signature verification, and separate production/development registry audits. IT must enable and govern Dependency graph / Advanced Security before GitHub dependency review can be made a required check. Network-backed audit/signature checks deliberately fail when the registry cannot execute them.
- On 19 September 2026, CI regenerated and verified a lockfile with the patched production dependencies and the eligible development fixes. The production audit passed; the development audit still found two high-severity `image-size` 2.0.2 advisories (via `vinext`). Its patched 2.0.3 release is inside the mandatory seven-day minimum-release-age quarantine until approximately 21 September 2026 15:58 UTC. Do not weaken or exempt the policy. Once eligible, resolve the version, regenerate and review the lockfile, then require both audits and the complete CI suite to pass on the exact commit before release.
- Health readiness checks configuration and a database query only; they do not certify business reconciliation correctness. Liveness intentionally does not touch dependencies.
- Structured operational logging is added for readiness. Existing business services primarily use immutable database audit events and have not all been instrumented with operational telemetry.
- Real operational layouts and data have not been used. BIFF8/XLSX/PDF support remains bounded as documented in Stage 5; scanned/image PDFs and unknown variants are rejected.
- This application does not initiate bank payments, post to a GL, or connect to unapproved enterprise integrations. Go-live and Stage 7 remain explicitly out of scope.
